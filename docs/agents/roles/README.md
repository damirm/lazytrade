# Роли разработки Lazytrade

## Назначение

Файлы в этом каталоге описывают роли агентов, реализующих требования из
`docs/specs/implementation-plan.md`.

Роль определяет постоянную область ответственности, но не является разрешением
реализовать весь соответствующий модуль одним большим изменением. Главный
интегратор выдаёт ограниченную задачу с конкретными requirement IDs и этапом.

Перед началом работы любой агент обязан:

1. Полностью прочитать `docs/specs/implementation-plan.md`.
2. Полностью прочитать файл назначенной роли.
3. Проверить текущее состояние репозитория и уже реализованные контракты.
4. Не менять публичные межмодульные интерфейсы без согласования с интегратором.
5. Не редактировать файлы другой активной роли без предварительной координации.
6. Добавить тесты и выполнить проверки, указанные в своей роли.

## Правило Go cache

Запрещено задавать, переопределять или специально использовать переменную
окружения `GOCACHE` в локальных командах, scripts, CI и документации проекта.
Go-команды запускаются с обычной конфигурацией окружения пользователя. Ошибки
доступа к системному Go cache нужно сообщать интегратору, а не обходить через
другой `GOCACHE`.

## Волны выполнения

Рекомендуемая последовательность:

```text
Волна 1
├── Foundation & Storage: bootstrap, config, domain contracts
├── Exchange: exchange contracts и fake
└── Strategy: strategy contracts и backtest design

Волна 2
├── SQLite/sqlc
├── T-Invest read-only
└── Strategy runtime

Волна 3
├── TUI
├── Risk/P&L
└── Backtesting engine

Волна 4
├── Order execution
├── Reconciliation
└── Web/Control

Волна 5
├── QA/Hardening
├── Sandbox acceptance
└── Release documentation
```

Одновременно работают главный интегратор и не более трёх sub-agent’ов.

## Владение файлами

Владение означает преимущественную ответственность, а не исключительный
доступ. Общие файлы (`go.mod`, config schema, domain interfaces, migrations,
OpenAPI, CI) изменяются только после уведомления интегратора.

При конфликте приоритет имеют:

1. `docs/specs/implementation-plan.md`;
2. зафиксированные ADR;
3. уже принятые межмодульные контракты;
4. файл роли;
5. локальные предпочтения реализации.

## Обязательный формат задания агенту

Каждое назначение должно содержать:

```text
Роль:
Этап:
Requirement IDs:
Цель:
Разрешённые каталоги:
Зависимости:
Не входит в задачу:
Команды проверки:
Ожидаемый handoff:
```

## Обязательный handoff

В конце агент сообщает:

- роль, этап и реализованные requirement IDs;
- перечень изменённых файлов;
- принятые локальные решения;
- выполненные команды и результаты тестов;
- известные ограничения;
- новые риски или вопросы;
- следующий рекомендуемый шаг.

Агент не должен объявлять этап завершённым, если критерии приёмки этапа из
основной спецификации не выполнены.
