# ADR-0004: структурированные логи через `log/slog`

Статус: принято, 2026-09-05.

## Решение

Длительно живущий торговый agent использует стандартный `log/slog`. Logger
создаётся на CLI composition root из секции `logging` и передаётся в runtime
явной зависимостью. Поддерживаются уровни `debug`, `info`, `warn`, `error`,
форматы `json` и `text`, вывод в `stderr`, `stdout` или append-only файл.

JSON является форматом по умолчанию. Относительный путь файла считается от
каталога YAML-конфигурации; файл создаётся с правами `0600`.

## Причины и инварианты

Структурированные стабильные поля позволяют наблюдать startup/recovery,
сигналы, risk decisions и жизненный цикл заявок без разбора произвольного
текста. Logger не является глобальным singleton, поэтому runtime тестируем и
не зависит от CLI.

Credentials, account ID, DSN и полные конфигурационные payloads запрещено
писать в лог. Идентификаторы стратегии, инструмента, intent и order допустимы.
CLI-команды с табличным результатом продолжают писать результат в stdout; это
не журнал работы.

## Отложено

Rotation и доставка логов во внешнюю систему остаются ответственностью среды
запуска. Метрики и tracing могут быть добавлены отдельно, не заменяя audit log
в базе и durable trading state.
